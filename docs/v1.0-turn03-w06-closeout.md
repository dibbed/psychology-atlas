## W06-02 | Controlled Research Dataset/Record Export

**IMPLEMENTED / VERIFIED (local engineering):** scoped `POST /api/admin/research/exports/` with strict `target_kind`, positive `target_id`, UUID idempotency key, non-empty unique projection and server-side allowlist. It uses existing `AdminJob`, session/CSRF, capabilities, scope, lease-fenced worker, `AdminArtifact` storage, safe checksum reads, audit and retention policy. Dataset-wide and single-record snapshots are acquired with row locks, stable selection and explicit original source SHA/provenance. A snapshot persists independently of later research record edits and is bounded by record count and output size. Export format: private **JSON v1** only. CSV was **not authorized** and was **not** added.

The field allowlist excludes `payload`, `raw_document`, `raw_text`, `source_ids`, protected mapping and any arbitrary field. Names `name_en`/`name_fa` require `cms_research_raw_read`. A distinct artifact resource binding for sensitive selections rechecks **raw capability, export permission, dataset ownership/scope and current session at request, claim/worker/checkpoint, list/detail and download**. Revocation denies both queued processing and later file access; cross-scope ID manipulation returns denial. The internal request manifest is **never downloadable** through the public CMS artifact download endpoint before completion; only a ready output artifact can be downloaded with current authorization. Files are private and checksummed; request and completion are separately audited (`research.export_requested`, `research.exported`), with download Audit performed by existing service.

Idempotency replays return the same job or explicit conflict; deterministic IDs, retained output intent and checkpoints reconcile interruption before/after file commit without duplicate output or extra completion audit. Expired/revoked/tampered artifact download fails; cleanup uses existing retention holds and keeps historical metadata. The Persian RTL Dataset and Record UI permits an explicit two-step request, choose allowlisted columns, see job progress and follow a guarded download link. `UNKNOWN_OUTCOME` keeps the same request key.

**Principal files:** `backend/atlas/cms_research_export.py`, `cms_artifacts.py`, `cms_artifact_views.py`, `cms_jobs.py`, `cms_job_models.py`, `cms_capabilities.py`, `cms_audit.py`, `migrations/0058_w06_research_private_export.py`, `tests_v100_w06_export.py`; `frontend/components/cms/ResearchExport.tsx`, `ResearchRecords.tsx`, `ResearchRecordDetail.tsx`, `ArtifactCard.tsx`, `ArtifactLibrary.tsx`, `JobDetail.tsx`, `frontend/lib/cmsJobs.ts`, `scripts/cms_intake_browser_qa.cjs`.

**Acceptance covered:** distinct dataset and record exports, exact projection, stable snapshot, source SHA, output SHA and literal JSON inspection; denied raw, wrong role, cross-scope, forged ID, revoked/expired download, tampering, duplicate/retry, lost worker, staged-file recovery, checksum and audit. **13/13 focused export tests PASS** on disposable SQLite and dedicated PostgreSQL 17 after the final security refinements.
