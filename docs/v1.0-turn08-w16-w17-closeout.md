## Source inspection / F03 root

Actual `cms_learning_fingerprint._dependency_snapshot` used `id`, `is_active`, `updated_at` for a linked Concept. `Concept.subtype` is a semantic eligibility field and can change through `QuerySet.update` without touching `updated_at`. Therefore an obsolete Distortion Practice dossier could stay current and pass Recheck.

The fix includes `subtype` in Concept dependency snapshots and validates that the target and each **active** choice Concept are active cognitive distortions. Inactive historical choice rows stay fingerprinted and retained; they are not deleted or rewritten. `select_for_update` aligns the semantic read with the existing publication-policy lock. A recheck/preview never mutates `StudyActivity`, `UserConceptProgress`, SRS or the canonical practice content.

## W16-01 source-level closure and change

`parse_selection` already enforces exactly one domain (learning / brain / assessment), a maximum of 20 items, unique typed identities, a SHA digest and idempotent request key. Resolution already binds `ContentState.current_revision` and its base digest. For editorial domains, `cms_domains.dependency_snapshot` traverses typed FKs to their endpoints/ancestors, source links, source identity hashes, `SourceState`, `SourceSuccessor` and protected field hashes; `governance_dependency_snapshot` and ReviewPolicy supply live rights/review dependency digests.

A gap existed: initial Selection stored live-dependency digest but **not** the current `editorial_review` or `source_rights_evidence` status. After adding a ReviewTask, Recheck could still report `all_snapshots_current=true` and prepare a new dossier.

Selection creation now seals both safe statuses under the same policy lock and a single, bounded rights-inspection budget. Recheck compares against that original baseline, flags `EDITORIAL_REVIEW_DRIFT` or `SOURCE_RIGHTS_DRIFT`, rejects unverifiable source-coverage, and marks legacy receipts without that baseline `REVIEW_RIGHTS_BASELINE_MISSING`. Historical sealed bytes and read access are preserved; fresh preparation fails closed. Source rights counted here are **only** metadata/public-display evidence, and `publication_rights_cleared` is always false. A synthetic test ReviewTask or rights fixture never confers scientific/legal permission.

## W17-01 bounded exact-candidate contract

**Route:** `GET /api/admin/publication/preparations/{dossier_uuid}/candidate-preview/`

A live session must own the exact immutable dossier, retain its domain-specific publication-selection authorization and hold `cms_{domain}_preview`; an unrelated user gets 404 for IDOR privacy, an owner without preview capability gets 403. Any changed version/revision/policy/content/rights baseline returns `CANDIDATE_PREVIEW_STALE` (HTTP 409), with no candidate content. Unknown query parameters are rejected.

Response `cms-private-candidate-projection-v1` includes: original Selection and Dossier IDs/digests, exact selected resource IDs and revision pins, bounded identity labels, and `public_projection: {available:false,payload:null}`. It explicitly reports `published:false`, `approved:false`, and `publication_available:false`. It never serializes raw research data, notes, item/answer text, private bibliographic evidence, arbitrary draft payloads or user history. The Persian CMS UI links this action to the sealed dossier, handles loading/error/empty/stale/permission failure, and states that it is not a public view.

This endpoint uses a separate private projection rather than altering the existing public `global_search`, `_get_atlas_graph`, Public API or their rights selectors. Their public candidate projection integration, alias disambiguation across domains and publication manifest consume-side remain open for later explicit authorization and implementation.
