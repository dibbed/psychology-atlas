# P05 SourceReference API contract — 2026-10-11

Implementation: `cms_source_models.py`, `cms_sources.py`, `cms_source_views.py`, `tests_v100_p05_sources.py`, migration `0041` and the existing CMS registration, URLs, capability catalog and audit. P01–P04 are preserved. No live database migration or publication was performed.

## Exact integration exports

Models from `atlas.cms_source_models`: `SourceState`, `SourcePlan`, `SourcePlanReceipt`, `SourceHistory`, `SourceSuccessor`. Source identity is stored as `source_pk` integers in retained history/state, so deleting an unused canonical source cannot cascade away its history. Plans and receipts/history/successors are append-only. Plans have UUID IDs, schema/version 1; applying creates a unique receipt and changes the exposed plan version to 2.

Services from `atlas.cms_sources`: `source_snapshot(source)`, `source_impact(source)`, `source_fingerprint(source)`, `preview_source(actor_id, session_id, data, request_id)`, `apply_source_plan(actor_id, session_id, plan_id, expected, request_id)`, `plan_data(plan)`, `source_data(source)`, `SOURCE_AUDIT_ACTIONS`, `SOURCE_AUDIT_REASONS`, `SOURCE_FIELDS`.

View exports from `atlas.cms_source_views`: `SourceListView`, `SourceDetailView`, `SourcePreviewView`, `SourcePlanView`, `SourcePlanApplyView`, `SourceHistoryView`, `SourceExportView`.

Audit actions: `source.preview`, `source.created`, `source.updated`, `source.archived`, `source.deleted`, `source.merged`, `source.split`, `source.successor`. Reasons: `SOURCE_CREATE`, `SOURCE_UPDATE`, `SOURCE_ARCHIVE`, `SOURCE_DELETE`, `SOURCE_MERGE`, `SOURCE_SPLIT`, `SOURCE_SUCCESSOR`. These exported sets and `SOURCE_FIELDS` are registered in the existing closed audit vocabulary and safe diff field names. Audit values never contain citations, evidence, metadata or field values. Events use the already accepted empty `target_kind`, `target_id` for the canonical source and `target_key` for the plan UUID; action names identify the source domain.

Existing capabilities only: reads `cms_source_view`; export additionally `cms_source_export`; every preview/apply `cms_enter`, `cms_source_view`, `cms_source_preview`, `cms_source_validate`, plus operation authority: create `cms_source_create`; update/merge/split/successor `cms_source_edit`; archive `cms_source_archive`; delete `cms_source_delete_preview` and `cms_source_delete_unused`. Sessions and current permissions are checked again in services under `policy_lock`. No group-name or UI-only authority.

## Routes under `/api/admin/`

| Method/path | View | Response |
| --- | --- | --- |
| GET `sources/` | SourceListView | paged list |
| GET `sources/export/` | SourceExportView | paged whitelisted bibliography JSON |
| GET `sources/{int:source_id}/` | SourceDetailView | detail + source-version ETag |
| GET `sources/{int:source_id}/history/` | SourceHistoryView | paged retained history, also after deletion |
| POST `sources/preview/` | SourcePreviewView | persisted plan + plan-version ETag |
| GET `sources/plans/{uuid:plan_id}/` | SourcePlanView | persisted plan + ETag |
| POST `sources/plans/{uuid:plan_id}/apply/` | SourcePlanApplyView | plan + receipt + ETag |

Use existing cookie/MFA/CSRF transport. All responses are `no-store`. Apply has an empty JSON body and `If-Match: "1"`; no direct POST/PATCH/DELETE of canonical source objects. A lost response is resolved by GET plan, never blindly replayed. Every write goes through a persisted preview, then the same validator recomputes under policy lock → Brain curation lock → source rows in PK order. No source/link bulk updates.

List/export accept `page`, `page_size` (existing 1–100 contract), `q` (title only, max 200), `doi` (exact normalized DOI), `pmid` (exact normalized PMID), `archived` (`0`/`1`). `doi` and `pmid` can be combined; `q` cannot be combined with either. DOI prefixes/URLs/case normalize; PMID accepts digits or a PubMed URL/prefix. URL normalization preserves version query parameters. No network lookup occurs.

List rows return `usage_count: null` and `impact_available: null`: impact has not been loaded. The scoped detail view computes the full consumer inventory and counts; bibliography pagination never scans private archive/review payloads or reveals domain usage counts.

## Shapes

Source list row:

```json
{"id":12,"title":"Synthetic fixture","organization":"","citation":"","url":"https://fixture.invalid/source","publication_year":null,"source_type":"","authors":[],"doi":"","pmid":"","verification_status":"","resource_version":"","provenance_versions":{},"version":0,"archived":false,"usage_count":null,"impact_available":null}
```

Detail is `{"source": <row>, "impact": <impact>, "fingerprint": "sha256", "successors": [...], "reason_codes": [...]}`. Raw source metadata is retained internally and participates in fingerprints, but is not returned as arbitrary editable metadata. `provenance_versions` exposes only existing string/integer `resource_version`, `source_version`, `version`, `dataset_version` pins. `resource_version` is a typed SourceState extension; an existing pin cannot be contradicted. It is not silently copied into or erased from legacy metadata.

Impact:

```json
{"canonical":[{"key":"DisorderSource:7:source","model":"DisorderSource","id":7,"field":"source","source_id":12,"owners":[{"model":"Disorder","id":3,"review_status":null,"is_active":true}],"claim":{"note":"Synthetic claim"},"protected":false,"mutable":true}],"review":[],"archives":[],"successors":[],"counts":{"canonical":1,"review":0,"archives":0,"successors":0},"protection":[]}
```

Review entries identify `ReviewTask`/`ReviewDecision` and `GovernanceRevision`, ID, JSON field/path, source ID and retained/manual status. P04 entries also include their evidence locator/supported fields. Archive entries identify model/ID/field/path and `mutable:false`, without returning raw payloads. Review decisions and archive bytes/JSON are never rewritten. Governance evidence, holder evidence and source-ID bindings are discovered in revision JSON, with record/decision context included in fingerprints; these references permit retain/manual handling only.

Preview input:

```json
{"operation":"update","source_id":12,"changes":{"title":"Synthetic corrected title"},"candidates":[],"field_choices":{},"mapping":[]}
```

Allowed operations: `create`, `update`, `archive`, `delete`, `merge`, `split`, `successor`.

`changes` permits only title, organization, citation, url, publication_year, source_type, authors, doi, pmid, verification_status, resource_version. Metadata replacement is forbidden. Normalization is shown in the persisted preview. Create requires no source_id and a title; other operations require an existing source. Archive/delete/split/successor do not accept changes. Sources archived by CMS cannot be edited or used as move targets; archive never changes a scientific review flag.

Merge: source_id is the survivor; candidates is a nonempty list of other existing source IDs. A matching exact DOI/PMID or a complete matching title/authors/year/version identity is required; conflicting identifiers or resource versions block. Every differing editable field requires `field_choices: {"field_name": <selected source ID>}`. Optional changes must agree with explicit choices. Every candidate usage must appear exactly once in mapping. Split: candidates is at least two existing, distinct publications; create targets using their own preview/apply first, then map every original claim explicitly. Successor: exactly one candidate; records correction/retraction lineage without changing protected canonical claims or their statuses.

Mapping entries for canonical consumers:

```json
{"key":"DisorderSource:7:source","action":"move","target_id":12}
```

`retain` has no target_id. Immutable archive/review/governance references permit retain only. Missing mappings block; no automatic deduplication or claim/note concatenation. A uniqueness conflict is displayed and must be resolved in a new explicit plan, including retain/manual handling. Protected claims cannot be moved or downgraded by this manager. Successor is the safe operational path for a protected source; later claim re-review belongs to its domain owner.

Preview/plan output:

```json
{"id":"uuid","schema_version":1,"version":1,"status":"preview","operation":"update","source_id":12,"request":{},"fingerprint":"sha256","preview":{"normalization":{},"comparisons":[],"identity_conflicts":[],"mapping":[],"blockers":[],"manual_plan":[],"counts":{"moved":0,"unchanged":0,"blocked":0},"rereview":[],"can_apply":true},"created_at":"ISO timestamp","receipt":null}
```

The request is the validated, normalized operation spec. Fingerprints include canonical source values, preserved metadata/version pins, incoming usage membership, complete link/claim context and Assessment findings, review evidence/tasks/decisions, archive references and payload hashes, successor/state history, and identity competitors. Apply rejects a changed fingerprint before attempting writes, even when source timestamps are unchanged. A persisted blocked plan is reviewable but cannot apply. New previews are immutable new UUIDs.

Applied receipt: `{"source_ids":[12],"counts":{"moved":0,"unchanged":0,"blocked":0},"history_ids":[1],"successor_ids":[]}`; plan status `applied`, version 2. Merge/split retain predecessor sources and original per-object snapshots/history; no history or evidence decision is deleted. Bibliography export includes only id/title/organization/citation/url/publication_year/source_type/authors/doi/pmid/resource_version, never metadata, archive payloads, rights proof or review decision content.

History response uses existing paging: `{"count":1,"page":1,"page_size":30,"results":[{"id":1,"source_id":12,"version":1,"plan_id":"uuid","operation":"update","before":{},"after":{},"actor_ref":"pseudonymous","created_at":"ISO timestamp"}]}`. History snapshots returned by the API use the source whitelist; private legacy metadata remains retained in the database.

Errors use existing `{code,message,request_id}`. Shape/type errors: `INVALID_FIELDS`, `INVALID_INPUT`, `INVALID_QUERY`, `INVALID_MAPPING`, `INVALID_FIELD_CHOICES`. Lookup: `NOT_FOUND`. Precondition: `PRECONDITION_REQUIRED` 428; `INVALID_PRECONDITION` 400; `STALE_REVISION` 412; `STALE_SOURCE_PLAN` 412. Operation blockers: `SOURCE_PLAN_BLOCKED` 409; `SOURCE_PLAN_APPLIED` 409. Permission/session/CSRF and audit failures use existing codes. Preview blocker codes: `SOURCE_PROTECTED`, `SOURCE_IN_USE`, `SOURCE_ARCHIVED`, `IDENTITY_CONFLICT`, `IDENTITY_UNCONFIRMED`, `RESOURCE_VERSION_CONFLICT`, `FIELD_CHOICE_REQUIRED`, `MAPPING_REQUIRED`, `IMMUTABLE_REFERENCE`, `UNIQUENESS_CONFLICT`, `CONSUMER_VALIDATION`, `NO_CHANGES`. Preview blockers have `{code,key,message}`. Denied/failed API audit remains the P04 independent post-rollback channel; success audit and mutation/history/receipt are one transaction.
