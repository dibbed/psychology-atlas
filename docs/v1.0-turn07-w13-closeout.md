## W13-02: claim-context scientific provenance

`cms_learning_evidence.py` now uses versioned `claim-context-v2` SHA-256 fingerprints, not explanation-only hashes. QuizQuestion context covers parent/question prompt, title, choices, active answer key and linked disorder; Flashcard includes front/back, hint, difficulty and Concept/Disorder; Daily includes prompt, explanation, active and inactive choice history and relations; Distortion Practice includes target, choices, option Concept identities and live subtype/availability. Concept/Disorder visibility and SourceReference metadata/right-state drift change freshness. Linking remains **private editorial evidence**, never scientific approval, public usage rights or publication authorization.

Additive `0060_w13_claim_context_fingerprint` introduces `fingerprint_version` and `change_reason` without changing any existing `0059` digest or append-only link. Existing rows default to `claim-text-v1` and remain `requires_review` until explicit actor-attributed recheck. If any `claim-context-v2` row exists, downgrade to `0059` refuses to discard meaningful version information.

Writes require live privileged session, CSRF, effective learning/source permissions, source impact scope, an editable private/no-history item, current If-Match ETag, and active/allowed source state. ID/source drift, stale If-Match and rights conflicts fail closed. Repeating an unchanged revision is idempotent; removal of an existing source **must supply a nonblank reason**. Revision and AuditEvent are transactional: a simulated Audit failure rolls back both. A real two-connection PostgreSQL race lets only one competing update commit, without a lost update or duplicate audit.

**History:** `cms_learning_evidence_history.py` exposes read-only, permission-aware, paginated revisions (50/page), actor/time, current-rights-redacted locators, source additions/removals, fingerprint version, status and reason; older rows are never rewritten. The service reuses the same current claim context and source/rights state within a History response to avoid redundant per-revision lookups. Independent tests cover history IDOR/role denial, redaction, atomicity and scaling.

**Persian UI:** `LearningEvidenceCard.tsx` and its Quiz/Flashcard/Practice parents refresh Evidence after content saves, invalidate old asynchronous replies and guard unsaved claims, staged source IDs, locator drafts and reason edits across item navigation, type switches, browser refresh and page leave. ## Learning transfer: explicitly safe partial boundary

The existing `psychology-atlas-learning-authoring-v1` import/export, artifact, checksum, worker, idempotency and private-only restrictions remain. A selected item with current scientific source binding returns HTTP `409 LEARNING_EVIDENCE_TRANSFER_UNSUPPORTED` **both before enqueue and at the worker**. This prevents silently stripping provenance. Existing v1 evidence-free imports create new private drafts only, never Activity, SRS, source approval, or real rights grant. Historical evidence remains append-only if a curator deliberately removes links with a recorded reason.

A draft of `psychology-atlas-learning-authoring-v2` is in `docs/v1.0-turn07-w13-transfer-v2-contract.md`. **DESIGN_ONLY / NOT_IMPLEMENTED**: portable SourceReference identity, cross-environment locator permission, legal intended-use/material and re-verification policy require explicit trusted/owner decisions. Do not remove the v1 guard or label portable citation transfer complete without those prerequisites. This external boundary does not fabricate an implementation.

## Daily Challenge

`learning.today_challenge` uses the existing server `timezone.localdate()` rotation over eligible active rights-allowed content ordered `(sort_order, id)`; `date.toordinal() % pool_size` chooses the daily item. The pool is intentionally dynamic. Tests cover time zones and rollover, ordering changes, archived/inactive/empty pools, real governed rights restriction, no API answer-key disclosure and immutable historical attempt/selected-choice data.
