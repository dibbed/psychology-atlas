## State, accessibility and session behavior

- Loading, filtered empty results, failed reads with explicit retry, forbidden/not-found scope, field validation, 412/409 conflicts and expired sessions have distinct displays. Error summaries are focusable and field errors use linked labels, `aria-invalid` and `aria-describedby`.
- Saves are explicit and guarded against a second click. A lost/timeout or unreadable successful write response is an unknown outcome, disables resubmission and requires inspection of the real server snapshot/history. The browser test drops an actual successful response after its database commit and verifies reconciliation without a duplicate revision. A new draft with an unknown response has no known ID; the UI requires checking list/audit before creating again.
- Conflict comparison retains the user's form only in memory, retrieves a fresh authorized snapshot and requires a field choice for overlapping changes. Non-overlapping changes use the appropriate side. Accepting comparison updates the exact base ETag/digest before the next explicit save. Canonical reconciliation blockers remain blocked; no override/publication service is fabricated.
- Internal navigation/reset/logout use a native modal dialog; Escape keeps the form and focus moves to the safe action. Browser reload/back/window close use `beforeunload`; its wording is controlled by the browser. Reload cancellation was executed; browser Back and actual window-close gestures were not separately executed.
- Expiry or cross-tab login/logout/account change clears mounted private snapshots and pending leave actions. Broadcast messages contain only an invalidation signal. Before sending a content mutation, the current account is rechecked against the editor's account; no draft is automatically replayed. No durable autosave or cross-account draft recovery is supplied.
- The shell is RTL; scientific names, identifiers and metadata use independent LTR/bidi handling. Original English names are preserved. Dates use the browser's local timezone, with server ISO timestamps retained.
- Visible keyboard focus, modal focus/Escape, labelled fields and keyboard list→detail were exercised. Native table regions are focusable and scroll horizontally at narrow widths; vital detail links are in the first RTL column. Controls are at least 44 pixels high.
- Desktop 1440×1000 and Chromium viewport 320×850 were exercised. Login, dashboard, list, editor, preview, history, audit list/detail, expired and forbidden displays had no document overflow. Final desktop/editor/list screenshots were visually inspected for clipping, RTL/LTR, hierarchy and wrapping. This is not a WCAG certification or screen-reader test.
