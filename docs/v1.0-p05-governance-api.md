# P05 rights and terminology API contract — 2026-10-11

Services: `atlas.cms_governance`; HTTP views: `atlas.cms_governance_views`; models registered through `atlas.models`, additive migration `0041` and `cms_urls`. No canonical content is written by these services. Attachments are deferred to private P06 artifacts; no upload field is accepted.

## Integration helpers (frozen contract)

`resource_binding(resource_type, resource_id, lock=False)` returns `{resource_type, resource_id, domain, resource_version, resource_digest, name_en, name_fa}`. Types are a closed registry, never arbitrary model labels. Assessment version/form/study/finding/access use their stable `key`; Assessment alias uses its version key (family slug if no version). DSM records use `corpus.key:corpus.version_name:master_id`. Other resources use a canonical SHA256 version. `resource_digest` is separate and hashes all canonical concrete values except timestamps plus declared parent context. A stable key never makes changed content fresh.

`governance_dependency_snapshot(source_ids, lock=False, resource_type=None, resource_id=None)` accepts a bounded collection of integer SourceReference IDs and returns `{source_ids, missing_source_ids, source_digest, governance_digest, digest}`. Scopes match a supplied evidence source **OR** the exact canonical resource type/ID. P04 passes `state.kind` and `obj.pk`; drafts without canonical targets pass sources only. This includes governance whose evidence is absent from scientific submission. `source_digest` hashes **all** current SourceReference canonical concrete fields (including organization/authors/metadata), excluding only creation/update timestamps. `governance_digest` hashes affected rights/terminology scopes, current immutable revisions, live policy/reviewer permissions and computed eligibility. Thus source edits, decisions, revocations and date boundaries invalidate P04 dependency bindings. Source snapshots are internal hashes; raw metadata is never returned through lookup. Source management modules are not eagerly imported.

`rights_eligibility(resource_type, resource_id, resource_version, material, intended_use, lock=False)` returns `{registered, eligible, permitted, status, blockers, record_ids}`. Exact version/material/use only. `registered=false, eligible=true, permitted=false, status="legacy"` means preserve the existing legacy public gate, **not** grant permission. Only append-only approve/revoke decisions establish an effective scope; pending or rejected proposals never withdraw public material. Reopening/editing retains the previous effective decision snapshot, still checked against current source/target/policy/reviewer and dates. A later explicit approval/revocation replaces it. An effective same-resource/material/use review for another version is stale rather than legacy. Explicit approved unknown, restricted, conflict, revoked, expired, not-yet-effective, review-overdue, or stale scopes deny. Fresh allowed exact approval alone returns `permitted=true`. Multiple incompatible allowed/restricted decisions return conflict. Item/translation decisions do not hide metadata. Public selectors intersect `eligible` with the existing scientific/public gates. Metadata, text, translation and learning items use separate exact `public_display` scopes; AssessmentAccess retains its exact recorded material/use. Helpers with `lock=True` run inside a transaction; acquire role-policy before Brain/source locks. The public overlay reads scope registration once per normal request from SQL and re-evaluates registered scopes; no process-local cache can hide a later request's revocation.

## Routes

All paths are under `/api/admin/governance/`, with existing cookie/MFA session, CSRF, no-store and request IDs. Views export `urlpatterns`, included by `cms_urls`.

| Method/path | Body/query |
| --- | --- |
| GET `resources/` | `resource_type` required; `q`, `page`, `page_size` optional. Typed canonical lookup, current version/digest; scope denial looks like not found. |
| GET `evidence/` | `q`, `page`, `page_size`; requires source view; returns id/title/url/doi/pmid/verification_status, no metadata. |
| GET/POST `rights/` | Paged queue / create submitted rights proposal. |
| GET/POST `terminology/` | Paged queue / create submitted terminology proposal. |
| GET/PATCH `{rights\|terminology}/{uuid}/` | Detail / partial proposal update. Update clears assignment and submits a fresh immutable revision; approved/revoked require reopen first. |
| GET `{rights\|terminology}/{uuid}/history/` | Paged immutable revisions and decision events. |
| GET `{rights\|terminology}/{uuid}/reviewers/` | Paged eligible reviewer IDs/usernames, explicit conflict codes. |
| POST `{rights\|terminology}/{uuid}/assign/` | `{reviewer_id}`; queued/in-review only. |
| POST `{rights\|terminology}/{uuid}/decide/` | `{outcome: "approve"\|"reject", reason, self_review_ack: boolean}`. Assigned actor only. |
| POST `rights/{uuid}/revoke/` | `{reason}`. Rights-revoke plus exact domain authority; immediately blocks eligibility, preserves decisions. |
| POST `{rights\|terminology}/{uuid}/reopen/` | `{}`. Returns submitted; clears assignment. The prior effective rights decision remains enforced with current freshness checks until a new explicit approval/revocation. |

All mutations except create require strong `If-Match: "<version>"` (missing 428, invalid 400, stale 412). GET/detail and mutation return `{record, policy, reason_codes}` and ETag. Lists accept only `resource_type`, `resource_id`, `status`, `computed_status`, `q`, `mine=1`, paging; domain scope and computed eligibility filter **before** pagination/counts. `computed_status=review_overdue` provides the overdue queue; `expired` is separately accessible. Every authorized candidate is evaluated in chunks, without silent candidate truncation. Workflow `status` is `submitted/in_review/approved/rejected/revoked`; `computed_status` is independent: `unknown/allowed/restricted/conflict/expired/revoked/stale/not_effective/review_overdue/submitted/in_review/approved/rejected`.

Common create fields: `resource_type` (see registry below), `resource_id` positive integer, `resource_version` copied exactly from lookup, `evidence: [{source_id: positive integer, locator: nonblank <=1000 chars}]` (0–20 for unknown rights, 1–20 for allowed rights/terminology), and `reason` from the closed rejection/selection codes below (default `CORRECTION_REQUIRED`). A resource type/ID is immutable; PATCH may change resource_version to its current binding, evidence, reason and the type-specific proposal fields. No domain, reviewer, approval, scientific, authorization or arbitrary model field is writable.

Rights fields: `material` = `metadata/image/text/translation/item/instruction/questionnaire/manual`; `intended_use` = `public_display/digital/commercial/redistribution/derivative/translation/owner_access/metadata_listing`; immutable exact scope. `status` proposal = `unknown/allowed/restricted/conflict`; `rightsholder` and `holder_identification` <=1000; `holder_evidence` same shape/limits as evidence; `public_access` = `unknown/public/private` (access never implies permission); `reviewed_on`, `effective_on`, `expires_on`, `review_on` nullable ISO dates; `limitations` <=4000, `territory` <=255 (blank valid when irrelevant), `conflict_note` <=4000 (required for conflict). **Unknown defaults to genuinely unset** holder/identification/evidence/limitations and null dates; never invent legal facts. Known ordinary source evidence can be retained separately from holder evidence. **Allowed proposals and approvals require** nonblank holder/identification/limitations, actual holder evidence and ordinary evidence, reviewed/effective dates. Expiry is inclusive: expired when today > expires_on; overdue when today > review_on. Future reviewed_on invalid; expiry/review cannot precede effective_on. Allowed approval must be effective and unexpired/unoverdue.

Terminology fields: `name_en`, `name_fa` nonblank <=500; `term_kind` = `display/alias` (immutable semantic scope); `alternatives` up to 20 distinct strings <=500; `selection_note` nonblank <=4000. Approval of transliteration is never implicit. Detail includes `preview: {dir:"rtl", name_en_dir:"ltr", name_en, name_fa, term_kind, alternatives}` as plain text, plus bounded same-domain candidate conflicts. Canonical name, alias, scientific status and AssessmentLanguageForm authorization never change.

Reason codes: create/update `CORRECTION_REQUIRED`; approval `RIGHTS_SCOPE_VERIFIED` for rights and `TERMINOLOGY_SELECTED` for terminology; reject/revoke `LOCATOR_INVALID`, `EVIDENCE_INSUFFICIENT`, `CLAIM_UNSUPPORTED`, `CORRECTION_REQUIRED`. Frontend displays Persian labels; actual scoped proposal status and exact approval are the authority, not a reason label. Business history retains the exact reason; shared audit maps approval reasons to existing `CORRECTION_REQUIRED`, without scientific approval labels.

Record shape: `id`, `kind`, `domain`, `resource_type`, `resource_id`, `resource_version`, `version`, `status`, `computed_status`, `payload`, `resource_digest`, `dependency_digest`, `assignee_id`, `policy_version`, `policy_mode`, `blockers`, `eligible`, `preview` (terminology), `candidate_conflicts` (terminology). Policy: `{mode, version}` from P04 singleton. History returns `{count,page,page_size,results}` with event action/outcome, revision/version, pseudonymous actor/assignee refs, exact payload and dependency hashes, policy, self-review acknowledgement, timestamps. No private user records are returned.

## Registry and authorization

Closed types: `source_reference` → source; `category`, `disorder`, `symptom`, `concept` → core; `dsm_record` → dsm; `therapy`, `technique` → therapy; `psychologist`, `theory`, `timeline_event` → history; `clinical_case` → cases; `flashcard`, `quiz` → learning; `brain_anatomical_entity`, `brain_network` → brain; `assessment_instrument`, `assessment_version`, `assessment_language_form`, `assessment_validation_study`, `assessment_psychometric_evidence`, `assessment_alias`, `assessment_access` → assessment.

Read/lookup: current `cms_enter` + `cms_{domain}_view`. Create/update/reopen: also `cms_{domain}_edit`. Assignment/decision: `cms_rights_decide` or `cms_terminology_decide`, plus `cms_review_decide_{domain}_{rights|terminology}` and domain view. Revocation: `cms_rights_revoke` plus scoped rights-review and domain view. No vocabulary is added. Cross-domain UUID lookup/history/mutation returns 404. Current assignee must retain all decision capabilities. P04 policy: two-person excludes every proposal contributor, including owner; solo-owner contributor decision requires effective owner and `self_review_ack:true`. Every decision rechecks session, permissions, exact target/evidence/policy under shared locks. Reopen/update is required after stale target/source/policy/reviewer changes.

Model registration imports: `GovernanceRecord`, `GovernanceRevision`, `GovernanceDecision` from `cms_governance_models`. Business histories are append-only. Successful governance audit uses existing `revision.created/review.submitted/review.assigned/review.decided/review.reopened/review.invalidated` and existing closed reason vocabulary, target_kind empty plus UUID target_key.
