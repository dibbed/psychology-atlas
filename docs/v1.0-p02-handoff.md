## Delivered actions/capabilities and covered models

Only `category` and `disorder` are registered content kinds. These adapters are the P02 foundation; the P07 domain editor and other domain adapters are not complete. Additional ready capabilities are `cms_core_view`, `cms_core_create`, `cms_core_edit`, `cms_audit_view`; `me` and `catalog` expose `ready_content_kinds` so readiness is not mistaken for full domain coverage. The seven P01 capabilities remain ready. Review/submit/publication/archive/export capabilities remain planned.

All endpoints below are under `/api/admin/`, require the P01 CMS session and retain CSRF checks for unsafe methods. Responses have `Cache-Control: no-store`; API requests get a server-generated request UUID.

| Method / route | Contract |
| --- | --- |
| POST `content/{kind}/` | `{payload, reason?}`; create a draft anchor and revision, no canonical row; 201 with ETag |
| GET `content/{kind}/{id}/` | scoped current snapshot and ETag; ID is an explicit canonical integer or a draft/state UUID |
| GET `content/{kind}/{id}/revisions/` | scoped immutable history snapshots, paging 30/max100 |
| POST `content/{kind}/{id}/revisions/` | `{payload, base_digest, reason?}` plus strong integer `If-Match`; patch the current proposal into a new immutable revision |
| POST `content/{kind}/{id}/discard/` | `{base_digest}` plus `If-Match`; only an unused draft; append a discarded revision and retain its history |
| GET `audit/`, `audit/{event_id}/` | sanitized, read-only audit; `cms_audit_view`; paging 30/max100 |

Category accepts `name_en`, `name_fa`, `description`. Disorder accepts `name_en`, `name_fa`, `short_description`, `overview`. Existing model length limits apply to names; proposed narrative fields are capped at 20,000 characters. Unknown models, private targets and fields such as `slug`, `category_id`, `reviewed`, `is_active`, `seed_managed`, actor and password are rejected. No arbitrary ORM target, field, system actor or dynamic import is accepted.

Reason codes are `DRAFT_CREATION`, `CONTENT_UPDATE`, `EDITORIAL_CORRECTION`; discard uses `DRAFT_DISCARD`. Free-text reasons are rejected, not copied into audit. API input cannot grant scientific review or publication state.

## Preserved invariants

- Role-policy lock precedes authority recheck, target locks, canonical-digest comparison, integer-version check/CAS, revision creation and success audit. A successful proposal and audit commit together; any later failure rolls both back.
- Missing `If-Match` is 428; malformed is 400; mismatch is 412 `STALE_REVISION`. Conflict includes current version/ETag and per-field `mine_changed`/`current_changed` booleans computed from the requested base. Snapshot values are obtained only from authorized no-store detail/history endpoints, not copied into conflict/audit/logs/localStorage.
- Changes from a legacy canonical writer cause `CANONICAL_RECONCILIATION_REQUIRED`; they cannot be silently overwritten. P02 does not implement canonical reconciliation or publication. Old unmanaged/newly seeded canonical objects without an anchor cannot be edited through this resolver.
- Draft creation never creates an active canonical object. A pending update continues to expose the unchanged legacy canonical content. Existing public API shape, selectors, eligibility and CaseAttempt/revision history are preserved.
- The existing P01 event table is renamed and extended, not replaced with a parallel security table. Success, denied and failed outcomes share the schema but failure recording occurs in a separate transaction after business rollback. Admin API and maintained MFA views explicitly avoid request-wide atomic wrapping.
- Audit insertion failure returns a sanitized 503 and rolls back the mutation. If the audit database is entirely unavailable, no durable event is promised: response is `AUDIT_UNAVAILABLE` and the mutation remains uncommitted.
- Audit diff contains only registered field names. Actor deletion uses SET_NULL while HMAC attribution and history remain. Guarded base-manager updates allow only this actor-nullification exception, not payload/outcome changes or deletes.

## Unexecuted checks and known limitations

No new browser UI, frontend build, remote CI, target HTTPS/proxy/cookie rehearsal, staging MFA/offline recovery, production deployment, push, PR or release was run. P02 adds backend primitives; the public frontend and its existing JWT/localStorage contract are unchanged. New CMS snapshot code does not use localStorage or write payloads to logs.

Independent source review initially found a base-manager bypass, unaudited non-database exceptions and missing maintained MFA denials. All three were reproduced or exercised with executable regressions, fixed and re-reviewed without remaining material findings. The review is source evidence; test results above are separate runtime evidence.

The disposable copied database and transient evidence helper were removed after the preservation check. The isolated PostgreSQL server was stopped; its synthetic-only cluster is retained under the host Temp directory as `atlas-p02-postgres-20261010-19344`.

Append-only enforcement is at the application/service/manager/admin boundary, not DBA or raw-SQL tamper resistance. No delete endpoint or general retention worker is supplied. Revision/history and audit are retained; the Master Plan's minimum audit retention and linked-history rules must be honored by a later explicitly authorized, audited retention worker. No raw private-note snapshot, export or learner-history correction adapter is registered.

Legacy CLI/domain writers and publication-overlay rollout retain their later phase ownership. Scientific validation, review decisions, child/parent bundles, dependency approval freshness, publication receipts and canonical application are not implemented by this proposal foundation. They must consume its locked anchor/digests, reuse existing domain guards, and preserve public eligibility.
