### Implementation

- `cms_brain_domains.py` declares closed typed field lists, relation sources, and create-only identities `slug`, `evidence_key`, `source_version`, `namespace`/`identifier` wherever applicable. `review_status`, `is_active` and `seed_managed` remain system/workflow owned. The implementation shares the existing dependency fingerprints, revision history, source/rights bindings, version checks, permission guards and scientific/source reviewer workflow. Registry import order is noncyclic.
- `cms_domains.py`, `cms_content_models.py`, `cms_audit.py`, `cms_governance.py`, `cms_capabilities.py` and `cms_urls.py` extend the real CMS services. Brain editorial and scientific/source review readiness is enabled. P16 publication capabilities, canonical activation, physical delete and withdrawal are not enabled.
- `GET /api/admin/content/brain/tree/` provides a bounded, paginated **private read-only canonical tree** and CMS state references, behind `cms_brain_view`. `?child=<id>&parent=<id>` requires `cms_brain_preview` and computes read-only before/after, cycle and incompatible laterality blockers, inactive endpoint checks, descendant impact, with no canonical change. The preview does not claim complete scientific/rights eligibility and refers editors back to the versioned draft and review workflow.
- `frontend/app/admin-console/content/brain/page.tsx` supplies Persian/RTL and keyboard-accessible form fallback, pagination, per-node navigation and no-write impact preview. Generic schema-driven list/edit/review pages cover all 13 types. `CmsShell` and ContentHome include the real ready-capability navigation.
- `0047_v100_p10_brain_domains.py` is an add-only migration extending ContentState.kind choices, DB CHECK vocabulary and legacy Brain state/revision backfill. The reverse migration refuses to drop retained Brain anchors. No scientific claim is reinterpreted or automatically approved.

### Real defects fixed during implementation

1. Browser QA exposed missing `cms_brain_preview` readiness; the owner was allowed server-side but the UI disabled the preview button. Fixed `cms_capabilities.READY_CAPABILITIES` and relevant CmsShell navigation. Reran production build and Chromium successfully.
2. A test erroneously assumed a proposed reparent would produce only one blocker when the link simultaneously caused a cycle and a laterality conflict. Preserved both correct blockers, tightened regression to require `CYCLE` without suppressing additional real blockers.
3. P09 import and UI regressions hardcoded 68 total schemas. They now count their own P09 34 and require P10 13 without regressing P07/P08 compatibility.
