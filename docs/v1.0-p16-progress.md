## 2026-11-11 | Distinct-source rights recheck budget + per-item selection reconciliation (PARTIAL)

**Branch:** `feature/v1.0-admin-cms`. This is a local bounded P16 verification and RTL operator-visibility increment, **not** a publication approval, release or deployment. The prior P16 source-metadata rights inspection remains scoped to `metadata/public_display` and keeps `publication_rights_cleared=false` even if every checked source is independently registered and permitted. No invented legal or scientific signoff and no new Apply/Freeze/Approve/withdraw control.

### Root cause and solution

The previous `verify_selection` counted the same `SourceReference` separately against the global `MAX_RIGHTS_SOURCES=16` inspection budget for every editorial proposal in a selection, so two proposal snapshots referencing the same source could report a later item's source-rights status as `unverifiable` solely due to duplicate work. This is not a rights-clearance bypass, but it yields incorrect inconclusive operator evidence. `_source_rights_coverage` now deduplicates **by real source ID across the one server-owned recheck**, caching the source governance result only inside that verification/policy-lock scope, while retaining a strict bound of 16 **distinct** sources. It still reports each item's own distinct-source denominator and fails closed when a new unseen source exceeds the bound, a source disappears, or its governance evidence cannot be read.
