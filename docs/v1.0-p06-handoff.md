## Cleanup boundary

Seven-day artifact access is distinct from physical retention. Cleanup is an explicit, versioned, scoped durable job, never an automatic filesystem sweep. Linked review/evidence/raw archives retain their bytes. A committed cleanup intent precedes unlink; recovery reconciles a missing server-owned file without replaying deletion. Metadata/audit/history remain. Storage-profile changes or integrity uncertainty fail closed. All destructive verification uses disposable synthetic files only.

The physical-delete adapter is deliberately Windows-only. It opens every ancestor/root directory and the exact verified leaf using native handles, denies replacement/write/delete sharing, verifies file identity/size/SHA, and deletes through SetFileInformationByHandle. Persisted directory/file identities prevent a replaced directory or leaf from producing a false purge receipt. There is no pathname-unlink fallback. Other platforms report cleanup_supported=false and reject physical cleanup with CLEANUP_PLATFORM_UNAVAILABLE; the UI explains the unavailable action. Native directory/leaf replacement and restart-receipt tests passed on Windows.
