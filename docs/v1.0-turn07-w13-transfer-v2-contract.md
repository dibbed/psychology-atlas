# W13-02: Versioned provenance-preserving Learning Transfer, draft contract

**Date:** 2026-11-16. **Status:** DESIGN_ONLY / NOT_IMPLEMENTED. **Owner decisions required.**
This document does **not** grant redistribution rights or scientific review.
Current transferable format remains `psychology-atlas-learning-authoring-v1`.
Its source-attached export guard `LEARNING_EVIDENCE_TRANSFER_UNSUPPORTED` (HTTP 409)
must remain active in both selection and worker until this specification is approved,
implemented, and verified across both database engines.

## 1. Current source behavior and scope

The v1 `cms_learning_io.py` contract exports up to 20 selected private,
inactive, unseeded, nonarchived, history-free learning parents (Quiz, Flashcard,
DailyChallenge, CognitiveDistortionPracticeItem) via an expiring,
SHA-256-checked private artifact. Inbound entities are new private drafts.
The exported `fields` snapshot reconstructs the educational content but does
not serialize `LearningEvidenceRevision` / `LearningEvidenceSource` and does
not transfer source identity, source locators, legal-review decisions, or
claim-context fingerprints. Export of an item with current source bindings is
therefore 409, deliberately fail-closed. Removing this check alone is prohibited.

## 2. Proposed v2 envelope (no production implementation)

Schema identifier: `psychology-atlas-learning-authoring-v2`. Preserve v1
envelope's `items[]`, `kind`, `key`, and `fields`; add
`source_manifest`, `claim_bindings`, `content_checksum`,
`export_policy_version`, and explicit `review_state="requires_review"`.

Each manifest source needs a portable registry identity based on verified
non-user bibliographic identifiers, the original SourceReference metadata
digest, source lifecycle state, and an evidence-origin environment label.
Never use a bare integer `SourceReference.pk` as a portable identity.
Unknown identifiers must require manual identity resolution.

Each claim must be addressed by a stable export-local path:
`<item-key>/quiz-question/<question-order-key>`,
`<item-key>/flashcard/back`,
`<item-key>/daily/explanation`, or
`<item-key>/distortions/explanation`. Store the
`claim-context-v2` fingerprint and a source-manifest reference with
the precise original locator, alongside explicit digest version. A target
environment must recalculate context after field normalization and
reject mismatches. Quiz choice order and correct-answer identity must be
included in the claim context; no source may silently move to another
question after an importer renumbers database IDs.

**Never** export or import immutable historical Attempt, Progress,
StudyActivity, UserFlashcardProgress, answer keys as user history, access tokens,
or historical rights approval attributed to another actor.

## 3. Import as a two-phase, private workflow

1. Upload to quarantined `AdminArtifact`. Enforce the existing 1 MiB
   bound, 20-item limit, JSON depth/node limits, schema allowlist,
   SHA-256 and an actor-scoped idempotency key before any domain writes.
2. Parse and stage a source-mapping table with source origin, candidate
   target SourceReference, exact bibliographic identifiers and conflict
   reasons. No fuzzy auto-merge, no ID-only match, no creation of a
   fabricated DOI/PMID or holder.
3. Re-evaluate `material` and `intended_use` against the **current**
   destination rights policy. Public online availability is not a grant
   for private transfer or redistribution. Unknown, revoked, expired,
   archived or deleted source/rights state must stop the relevant binding.
4. Require explicitly authorized review of each unresolved mapping and
   each source's permitted transfer use. `cms_learning_create`,
   `cms_learning_edit`, `cms_source_view` and the source impact
   capability are necessary but not a substitute for legal permission.
5. Import canonical learning entries strictly as new inactive drafts,
   inside a controlled transaction. Bind only validated portable claims
   to mapping-resolved sources in new `claim-context-v2` evidence
   revisions. Set review debt explicitly. Never import an assertion of
   `reviewed`, `allowed`, or publication from the source environment.
6. Record checkpoints, source-mapping decisions and a recovery-oriented
   manifest; retry by the same actor/job idempotency key. On an unresolvable
   mapping or checksum mismatch fail the entire unsafe binding and report
   partial stage state, rather than marking a source-less import successful.
7. On export, re-evaluate current canonical content fingerprint, rights,
   archive status and source mapping at worker time and again before
   making the private output downloadable. Expire/revoke output
   independent of user-owned historical evidence.

## 4. Compatibility and provenance rules

- v1 evidence-free import/export must continue to work byte-for-byte.
- v1 evidence-bound export must stay HTTP 409.
- v2 import without verifiable rights or source mappings is HTTP 409 and
  cannot silently drop `claim_bindings`.
- v2 source publication requires **separate** P16 scientific review and
  P05 rights decision in the target environment.
- Append-only learning evidence history must never be rewritten or
  conflated with exported snapshots; imported evidence starts a *new*
  revision lineage with explicit origin attribution.
- Workers must recheck current permissions and provenance after enqueue.
  Imported content never alters canonical Attempt, SRS or personal history.

## 5. Owner/external blockers (not engineering PASS)

**OPEN G05 / P05:** Exact policy for exporting private source locators
and redistributing source-derived material across environments.
No legal right or review decision was supplied in this turn.

**OPEN identity decision:** Approved portable source registry identity,
trusted target/source mapping and recovery procedure for collisions and
missing citations. A title or URL alone is not proof of identity.

**OPEN W16-09:** Public Learning adapter and its source/claim scientific
review compatibility; v2 transfer cannot grant publication.

**Verdict:** This is a concrete reviewable future contract, not a
working v2 transfer implementation. The v1 guard is the safe current
production behavior, and W13 cannot claim **portable provenance transfer**
without resolving these blockers and executing end-to-end v2 tests.
