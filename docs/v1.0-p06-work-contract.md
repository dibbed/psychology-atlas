## Frozen implementation interfaces

Shared models are in `atlas.cms_job_models`: AdminArtifact, AdminJob, ResearchRecordDecision. Model registration/migration/settings/audit/readiness/URL integration belongs to the controller. Artifacts are never FileField/public MEDIA URLs. Storage is a server-owned root outside webroot. JSON formats only; no remote fetch, arbitrary paths/commands, automatic promotion, fake review or activation.

Artifact module `cms_artifacts`: `artifact_scope(actor, artifact, download=False)` raises 404 for domain/owner mismatch; current upload/download capabilities are independent. `artifact_data(artifact)` returns id/kind/domain/resource_type/resource_id/resource_version/filename/sha256/size/state/version/expires_at/validation_code/created_at, never storage_key or file paths. `get_artifact(actor, artifact_id, download=False, lock=False)`; `artifact_bytes(artifact)` rechecks immutable checksum and bounded private file safety. `process_intake(job_id, lease_token)` executes bounded checkpoints through the job service; existing importer normalization and DSM parser reused without canonical writes. `evidence_snapshot(artifact_ids, resource_type, resource_id, resource_version, lock=False)` provides stable scoped readiness/expiry/checksum bindings; no raw bytes. Evidence artifacts are tied to an exact resource version.

Job service `cms_jobs`: `checkpoint_job(job_id, lease_token, effect)` runs effect(job) inside a short policy/row-lock transaction after validating actor/session/policy/lease/cancellation; callback saves effect/checkpoint/progress, returns normally; success/failure transitions belong to the runner. `process_intake` can call it repeatedly with chunks. Heartbeat and token renewal occur per checkpoint. Canonical writes are never part of this handler. `job_data(job)` returns safe id/kind/status/version/attempt/progress_done/progress_total/error_code/artifact_id/checkpoint summary/result/created_at/updated_at; checkpoint data only server-owned integer IDs/offsets/hashes. `enqueue_job(actor_id,session_id,artifact_id,request_key,request_id)`; explicit same-key+same-payload replay returns same job, changed digest is conflict. Requests cannot choose a handler/command/path. `run_once()` claims one job; expired leases reconcile their committed checkpoint before resuming, stale workers cannot commit. Three attempts maximum; transient-only automatic retry; deterministic permission/validation/integrity failure has no auto retry.

HTTP under `/api/admin`: GET/POST `artifacts/` (POST multipart `file`, `kind`, optional exact `resource_type/resource_id/resource_version`; upload creates quarantined record; validate separately), GET `artifacts/{uuid}/`, POST `artifacts/{uuid}/validate/`, POST `artifacts/{uuid}/revoke/`, GET `artifacts/{uuid}/download/`. Mutations except create require If-Match. Evidence JSON validates shape/bounds only and is never legal/scientific attestation. GET `jobs/`, GET `jobs/{uuid}/`, POST `jobs/{uuid}/retry/` and `cancel/` require If-Match. POST `research/imports/` `{artifact_id,request_key}` returns202 `{job:...}` + ETag/Location. GET `research/datasets/` and `research/datasets/{int}/records/`, GET record detail/history, POST `research/records/{int}/raw-preview/` `{purpose,reason}` audit-sensitive and POST `research/records/{int}/decisions/` `{action,mapping,reason}` with If-Match. Research list/detail return only safe metadata and derived decision state; raw text/payload only audited scoped raw-preview/download. Immutable existing archived bytes and imported payloads are never overwritten. Stage means candidate ready for future scientific review/publication, never canonical promotion or scientific approval.

Permissions reuse frozen vocabulary: artifact upload/download plus underlying domain view/edit (research uses research_view/intake), research_view/intake/map/derive/reject/defer/raw_read. Job reads/actions are limited to their actor (owner may inspect) and the original action capabilities, independently of UI. Every service rechecks current authority. No new generic job/admin permission is invented.

## Safety and verification

Physical cleanup is Windows-only: native handles pin every ancestor, storage root and verified file; deletion uses SetFileInformationByHandle, never a pathname unlink fallback. The committed intent records directory and leaf identities. Recovery writes a missing-file receipt only under the same pinned directory identity and never repeats deletion. Other platforms expose cleanup_supported=false and reject cleanup with CLEANUP_PLATFORM_UNAVAILABLE; JSON intake, metadata and retention holds remain available. No cross-platform physical-cleanup acceptance is claimed.

POST artifacts/{uuid}/cleanup/ accepts an empty body and If-Match, returns a registered artifact_cleanup job, and cannot clean an unexpired or historically referenced artifact. Historical governance evidence/holder references, completed or active intake and matching raw archives retain the file. A seven-day download expiry does not authorize deleting retained raw/review material. Purged metadata/audit/history remain.

Disposable SQLite and PostgreSQL/storage only. Explicit NON-SCIENTIFIC .invalid test evidence. Cover path traversal/symlinks/checksum corruption, upload bounds/schema/protected content, foreign domains/raw leaks, revoked/expired downloads, duplicate jobs/imports, lease stealing/stale commits, crash after committed chunks, cancellation, permission loss and audit rollback. Keep existing guards/public publishers/Study authority. Current statuses become verified only after matching checks run. Product docs and this ledger record limitations and tested state.
